# Update: Post-Run Terminal Analysis with Defense-Specific Suggestions — August 3, 2026

## What Changed

Built a post-run analysis system that automatically detects vulnerability patterns in completed FL experiments and generates defense-specific improvement suggestions with concrete parameter changes. The analysis prints directly in the terminal after every run and saves structured JSON for later database ingestion.

This closes the gap between "find weakness" and "suggest fix" — the framework now completes the full loop:

```
run attacks → find weakness → suggest fix → (user re-tests with suggested params)
```

### 1. New Script: `scripts/post_run_analysis.py`

A local, offline, rule-based analyzer (~470 lines) that reads a completed run directory and produces:

**What it detects (8 vulnerability patterns):**

| Pattern | Trigger | Severity |
|---------|---------|----------|
| Defense collapse | Final accuracy < 5% | Critical |
| Accuracy degradation | Drop > 10pp from peak, final < 70% of peak | Medium |
| High slipthrough | Malicious clients pass filter at > 30% rate | High |
| Trust failure | Any malicious client gets trust score > 0.5 | High |
| Poor trust separation | Benign-malicious trust gap < 0.1 | Medium |
| Stealth evasion | Stealth norms within honest p90 for > 30% of rounds | Medium |
| Backdoor success | Final ASR > 10% | High |
| Adaptive convergence | MAB converges to one attack > 30% of rounds | Medium |

**What it suggests (defense-specific, data-driven):**

Each defense gets tailored recommendations based on what actually happened in the run — not hardcoded one-liners. Examples:

| Defense | Finding | Suggestion |
|---------|---------|------------|
| Bulyan | Collapse under sign_flip | "Consider reducing malicious fraction assumption or switching to trust-based defense" |
| FLTrust | Poor trust separation (0.011) | "Increase fltrust-root-size from 1860 to 3720 for stronger server gradient signal" with `param_changes: [{param: fltrust-root-size, current: 1860, suggested: 3720}]` |
| MAB-RFL | Reputation too slow | "Increase mab-rfl-reputation-decay from 0.9 to 0.95, reduce trust-warmup-rounds from 3 to 1" |
| FedTrimmedAvg | ALIE dominant | "Increase trimmed-beta from 0.2 to 0.3 — but verify clean accuracy doesn't degrade" |
| FoolsGold | Adaptive evasion | "Adaptive mode diversifies attack combos, defeating similarity detection. Add norm-based pre-filtering" |

Each suggestion includes machine-readable `param_changes` arrays with current and suggested values.

**MITRE ATLAS integration:** Every finding is classified using `db/atlas_mapping.py`'s technique registry (11 ATLAS techniques) and gets a novelty status (`known_weakness`, `reproduced`, `candidate_new`, `needs_testing`).

### 3. JSON Output

Every run now gets a `summaries/run_analysis.json` file with structured data:
- Accuracy stats (final, peak, trajectory, collapsed flag)
- Attack behavior (mode, dominant attack, all counts, stealth)
- Defense behavior (trust scores or slipthrough rates)
- Findings with ATLAS technique IDs and novelty status
- Suggestions with `param_changes` arrays

This JSON is designed for direct ingestion into the `agent_recommendations` database table.

### 4. `run.sh` Updated

Post-run analysis now runs automatically after every `run.sh` invocation (before the optional LLM analysis). LLM analysis can be disabled with `CALL_LLM_ANALYSIS=0` to skip the API call and cost.
